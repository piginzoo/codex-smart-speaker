## 案例一：Bixby 代设闹钟（零代码方案的死结）

### 动机

闹钟需求出现后，最先想到的不是写代码，而是三星自带的 Bixby——它的看家本领就是调三星自家时钟，设/查/取消闹钟全是原生能力，闹钟响还是三星时钟的全屏界面。**理论上零行代码**。

### 尝试过程

1. **按 Bixby 实体键（机身左侧）呼出 → 报"录音被占用"**
   根因：管家的"24小时听唤醒词"循环正抓着麦克风，Bixby 要录音被三星拒绝——先到先得，本项目一切语音功能的公共敌人。
   临时解法：force-stop 管家放麦 → Bixby 能正常设闹钟了，功能本身验证可用。

2. **尝试免接触呼出（要害）**
   - 实体键是系统级硬件事件，**三星没开放任何 API 让普通 App 模拟它**
   - 尝试 adb 监听按键事件抓真实键值（两次引导用户配合按键，都没抓到）
   - adb 直接注入键值 1084 → 不是 Bixby 的码，息屏下也没弹出
   - "Hi Bixby" 语音唤醒：S9 这代大概率要求亮屏才监听，且常驻监听照样跟管家抢麦

3. **感知开/退倒是可以做**（无障碍服务监视 Bixby 窗口，弹出自动让麦、关闭自动恢复）——但这只解决共存，解决不了呼出。

### 死因判定

> 用户原话："**那必须再让我摁一下硬件，这不可行，我就想用语音来唤醒**，这我认为这个方案是不可行的。"

死结 = **呼出必须碰硬件**，与"免接触、息屏喊一声"的产品铁律根本冲突。2026-11-21 关闭此路线。

### 教训

- **系统级语音助手的入口是厂商私有硬件事件**，不在公开 API 面里——"功能存在"不等于"可编程触达"
- 共存问题（让麦）可解，入口问题无解——评估方案时要把"入口"和"交互"分开审
- adb 注入硬件按键事件在无 root 的量产机上基本是死路

## 案例二：自研 GLM 语音聊天 + 语音闹钟（"小智/小管家"模式）

### 动机与架构

Bixby 被否决后回滚到"自听方案"：管家自己监听语音、识别意图、本地设闹钟。交付形态：

```
喊"小智小智/小管家" → 中文全量ASR → GLM(glm-5.3-flash)解析意图
  → action JSON: set/cancel/list/clarify/chat/open_chatgpt/exit
  → 闹钟 = AlarmManager 精确闹钟 + 响铃前台服务(AlarmRingService) + 全屏确认页
  → TTS(SMT中文) 语音答复；对话中说"叫Codex来"可直切 ChatGPT live
```

细节上还真下了功夫且**大多修通了**：clarify 复述+本地确认（零二次 LLM 调用）、熄屏闹钟 Activity 被杀改前台服务响铃、Doze 下 Receiver 启动服务被拒改 Activity 跳板、TTS 回声 muteUntil 窗口、能量门滤环境音。**闹钟的引擎部分本身是稳的。**

### 死因判定（三层叠加，全在语音入口）

1. **唤醒词撞音，反复修不好**——"小智"和"Codex"在两个识别模型里互相撞音：说"小智"呼出的是 ChatGPT。用户连珠炮式反馈：
   > "你小智小智呼出的是Codex，你反复测一下，**每次都呼出Codex怎么回事啊**？你先把这个测鲁棒了。"

   换词（小智→小智小智→小管家）+ 收词表都没根治。**唤醒词的音素独立性是生命线，撞音=方案死刑。**

2. **转写幻觉漂移，变体表永远追不上**——中文模型对英文合成音的转写每次都是不同幻觉（"Hey Codex"合成音一度被听成"澳洲时间到可是想留到最后"）。变体表可以收敛**真人声**，收敛不了**无边界的幻觉**。

3. **双全量 ASR 并行的工程脆弱性**——为同时听中英文改双识别器并行，结果 cn 路的 `continue` 把 en 路**饿死**（Hey Codex 全聋）；重构为独立函数后仍不断回归。一个 App 里跑两套语音状态机（唤醒 + 对话），在 S9 + 离线小模型的算力下复杂度失控。

### 用户最终裁决

> "**我对闹钟这个功能彻底丧失信心了**，回滚到最开始那个做闹钟之前那个版本。"

2026-11-21 整体移除 GLM 聊天 + 闹钟 + 相关的 8 个文件，回归纯唤醒版（8 文件 886 行）。

### 教训

- **一个 App 两套语音状态机是复杂度深渊**：唤醒循环和对话循环对麦克风、音频模式、识别器的需求互相冲突，每修一个坑 expose 两个新坑
- 变体表调优的天花板：真人声可收敛，合成音/幻觉不可收敛——**识别质量不行时，产品体验没有中间态**（要么好用要么不能用，用户容忍度是零）
- 讽刺的是：死得最冤的部分是闹钟引擎（精确闹钟+前台服务响铃+全屏页），它败给了语音入口而非自己的 bug——**架构上把入口和引擎耦合在一起，让无辜模块陪葬**
